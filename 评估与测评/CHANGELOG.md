新增独立二维搭建界面，进入前选择侧视或俯视，支持方块分类、完整状态选择、实时二维水流、滚轮缩放、右键移动方块和画布、撤销重做及画布保存。默认使用 XK 红石材质，平面展示优先选择完整可辨认的一面，修复铁轨显示成侧边线、铜箱子缺少完整模型及初始画布恢复旧内容的问题。接入原版放置音效，冰、浮冰、蓝冰使用指定 MP3，地狱门使用普通方块放置声。

支持将单个 `.litematic` 文件直接拖入窗口，左上角浮现与界面配色一致的圆角提示。背景选择旁新增“停止渲染”，直接终止当前预览引擎，包括文件读取、CPU 渲染及完整 / 分块模型准备；任务进行中拖入新投影自动停止旧任务，连续拖入以最后一个文件为准。停止后可重新渲染，后台图片和动画导出继续运行。旧任务的回调、显卡上传和临时文件按所属任务隔离，保留已完成场景缓存及其他导出任务。

统一版本为 1.1.0.3，重新构建 Windows 便携版。

## 1.1.0.2 ui更新

更新界面配色、侧栏卡片、按钮、输入控件和弹窗样式，调整选择工具按钮排列。统一版本为 1.1.0.2，重新构建 Windows 便携版。

## 1.1.01 优化光照和组员缓存

汇总此前本地 1.0.17.16–1.0.17.19 的光照与缓存优化，统一版本为 1.1.01：修复大内存下光照路径导致完整模型迟迟不出现，增加基础资源图片缓存与有界批量区块传输，并行生成完整区块，缓冲场景索引读取；保留完整模型、光照、透明材质、动画和导出行为。

验证与计时边界见下面各轮记录和 [大投影打开速度调查.md](大投影打开速度调查.md)。提交说明按指定文本使用“优化光照和组员缓存”。

## 1.0.17.19 启动资源缓存与批量区块读取

基础贴图、动画顺序和生物群系色图增加磁盘缓存，以完整资源内容、材质顺序和引擎内容指纹校验；不保存场景生成的文字或皮肤。缓存采用有长度上限和 CRC 的压缩格式，损坏后正常重建，最多保留三组。内存中的 PNG 数据避免为每张图片创建临时文件；沿用退出清理设置，开启时同时清理资源缓存。

区块数据通过最多 128 页、2 MiB 的批次传输，上传仍在原有几何预算内进行。批次仅在读取与上传间暂存，闲置时释放；保留页校验、已发布长度、场景归属和快速切换检查，某个后续页损坏不会连带标记正常区块失败。

启动时打开投影会等待资源初始化完成，避免初次资源重载清除刚打开的投影。本机《璃月港》同进程交错对照：缓存重开约 6.3–7.2 → 3.8–4.3 秒，10,606 次逐页请求降为 83 次批量请求，远景像素完全一致；新进程资源缓存命中约 2.9–3.2 秒。首次建立资源缓存不享受命中收益。

## 1.0.17.18 大内存下完整模型迟迟未出现

修复大投影的光照算法只按可用堆选择：约 8 GB 堆下，《璃月港》会进入整个包围盒的密集光照扫描，逐列读取压缩方块页，反复解压而长时间停留在总览。分块模式对密集光照增加固定的 16,777,216 格工作量上限，超过后使用已有稀疏光照；保留的密集天空光初始化改为逐层连续读取，独立保存各列光照衰减，不改变结果。

补充 7936 MB 堆下的实际界面回归，必须显示真实 LOD0 几何和材质，覆盖首次打开、生成中的近景、缓存重开、漫游与关闭 LOD。逐格光照对照及《璃月港》模型、图集文件字节一致性通过。此修复解决光照阶段长时间未结束，不改变远景按距离简化的规则。

## 1.0.17.17 并行区块组装与缓存索引

完整图集与光照准备完成后，根据 CPU 和可用堆启用最多四个区块工作线程。共享只读光照、贴图和已烘焙模型，每个线程保留独立的组装、AO、模型继承解析和邻域缓存；统一按提交顺序写出，保留镜头优先级和逐块发布。限制待处理任务和网格数量，取消、失败和完成时等待所有工作线程退出。

区块复用带一格边界的 18³ 方块邻域，减少重复解压查询；普通方块跳过头颅检测中的字符串替换。完整索引采用 64 KiB 缓冲读写，实时区块仍直接写入可读文件，保留旧版格式、页边界和损坏数据检查。

本轮以 1.0.17.16 重新做同机对照：《璃月港》完整场景准备约 94.8 → 56.9 秒，开始细节到场景发布约 60.3 → 21.9 秒；引擎缓存重开约 4.88 → 0.23 秒。网格和图集文件逐字节一致，详细计时边界和原始结果见 [大投影打开速度调查.md](大投影打开速度调查.md)。

## 1.0.17.16 大投影加载等待

修复稀疏光照列和区段的坐标哈希冲突，吸收点收集完成后预存有限的直接天空光衰减区间，保留遮挡、侧向传播及未分配空气的采样。方块数据沿用原有每线程 64 页解压缓存，同页连续读取跳过重复哈希查询。

Windows 目录资源遍历复用已获取的属性，资源会话复用 `assets/` 清单；重新加载继续验证完整内容指纹，同时间同长度修改、新增与删除仍可使缓存失效。便携包补带 README 引用的截图和开发说明目录。

《璃月港》同机带采样引擎对照：首个完整材质区块约 58.3 → 30.3 秒，完整场景准备约 117.0 → 75.7 秒。前后模型与图集文件 SHA-256 一致。完整阶段边界、实际界面结果及验证见 [大投影打开速度调查.md](大投影打开速度调查.md)；该降幅不代表所有投影、首屏帧率或总览生成速度。

## 1.0.17.14 Alt 滚轮角点微调、GIF 半透明与后台导出

参照本地 Litematica 的选中角点与六方向步进，增加已有角点切换入口；滚轮每次移动一格，水平朝向与超过 60° 的上下视角分别控制水平轴和 Y 轴，保留漫游、自定义修饰键与优先处理。

验证包含 GIF 实际解码后的 0 / 1 / 26 / 64 / 127 / 128 / 254 / 255 alpha 覆盖率、低透明度颜色与固定掩码，六方向角点与反向恢复、主视图缩放优先级、后台快照 / 顺序 / 取消 / 失败 / 退出清理，以及实际桌面界面导出期间主引擎响应和修改选区。

## 1.0.17.10 固定中心旋转与透明残影修复

GIF 不再按每帧角度重新适应画面，改为按整周最大投影范围一次取景；相机始终围绕模型中心竖轴旋转，缩放、中心与俯仰固定。透明帧使用恢复背景的处置方式，清除上一帧内容，避免连续播放和循环交界残影。

桌面、RPC 与命令行默认改为 50 FPS、每帧 2 厘秒，一周从 64 帧增加为 480 帧；总时长由 3.2 秒延长至 9.6 秒，转速降至原来的三分之一。提升总帧数保持慢速旋转流畅，采用兼容浏览器的 GIF 帧间隔。回归覆盖长条负坐标模型的各角度实际像素边界、多种俯仰的固定中心和缩放、逐帧处置与两轮播放，以及实际界面的导出参数和时长说明。

## 1.0.17.9 紧凑场景与旋转 GIF

恢复普通 NBT、文件、网络和投影专用读取路径的生产限额，并补充低压缩率分页、常驻预算与 16 GiB 逻辑边界回归。全局光照改为一次扫描同时准备天空光与方块光，无发光方块时跳过空通道，规模足够时并行传播两个独立通道。

场景格式升级为 LMESH7：规则轴对齐单位面使用 40 字节无损记录，复杂、内缩和倾斜几何继续使用 80 字节通用顶点，透明 BSP 保留原有顺序；浏览器在显卡上传前展开紧凑记录。真实 32 格构建与 16 格输出、负坐标和重叠区域一致，本机稠密样例中位数为 225 ms 对 250 ms，因此生产默认继续使用 16 格，32 格路径保留为显式实验开关。

修复 GIF 误走 PNG 保存对话框、仅改变动画贴图而不旋转相机及菜单重复绑定。界面现在明确导出 360° 旋转 GIF，按当前角度生成 64 帧完整一周，并验证 GIF89a 文件头、帧数及帧间画面差异。

## 1.0.17.8 铜傀儡雕像模型

修复铜傀儡雕像只有粒子贴图、没有可见模型的问题。原版的方块 JSON 不包含雕像几何，模型由专用方块实体渲染器提供；此前既未接入该渲染器，也会丢失 JSON 未声明的姿势和朝向属性。
按本地原版 26.3 `CopperGolemModel` 的四套姿势和 `CopperGolemStatueBlockRenderer` 的变换补齐几何、UV、朝向与氧化贴图。八种氧化/涂蜡变种共用对应模型；没有保存方块实体 NBT 时仍按方块状态正常显示。
普通预览、PNG 导出、逐块预览和点选共用该路径；特殊贴图在流式图集固定前注册，渲染器内容指纹变化会使旧场景缓存失效。

用户《32铜人.litematic》实际包含 32 个雕像方块和 0 个生物实体。验证所有雕像均有模型，共 1,824 面；另覆盖八种变种 × 四种姿势 × 四个朝向、负坐标区块交界、固定图集、点选与完整/分块几何一致。

## 1.0.17.7 按视角逐块补充完整细节

完整区块生成后立即发布其几何页与索引，优先处理当前视角和视距内的待生成区块；镜头改变后重新排序剩余工作。
新细节上传成功后才替换对应总览，完成时保留原有显示实例和已载入缓存；LOD 开关直接调整档位，不重新构建或重新打开场景。
总览按 16 格所有权对齐，较大场景使用稀疏颜色单元，避免一个粗块跨越多个替换区域。总览使用独立颜色着色，换入完整图集时不变色。

特殊贴图注册仅组装需要生成贴图的部分，跳过普通方块和透明排序；合并后台自动刷新以减少与构建争用，手动镜头操作继续即时响应。
进度区分全局光照、特殊贴图、区块生成与当前视角加载。全局光照仍需先准备，本轮没有将完整准备总耗时标记为已改善。
退出清理补充普通模式的 `renders/.gpu` 临时模型，导出图片继续保留。

验证覆盖增长文件读取边界、视角/视锥优先、取消与旧任务拒绝、缓存重开、低预算总览保留、LOD 不触发重建，以及六个视角与完整模型的图像对照。
资源就绪后的本机《璃月港》约 3.49 秒出现总览、51.45 秒载入首批材质区块，完整准备和当前视角载入约 107.93 秒，再次打开约 15.28 秒；这些数字分别反映首批可用与全部准备的时间。

## 1.0.17.6 大文件读取与退出清理

修复《故宫》打开时的 `Root tag is not a compound: Unknown(31)`：压缩格式由文件头判断，保留实际读取异常，日志记录输入文件路径。
大型方块数组按 32 KiB 页压缩保存，空页和相同数值页单独简化；共享有界解码页，不再把全部解压数据同时保存在长整数数组中。
专用投影读取路径放宽逻辑数据限额，并独立限制常驻预算，保留普通 NBT 的较低配额；拒绝负长度数组和列表。

## 启动

完整解压 ZIP 到一个文件夹，双击根目录的 **投影预览.exe**。
也可以把 `.litematic` 文件拖到 EXE 上打开。请保留 EXE 旁的 assets、bin、runtime、webapp 文件夹。

适用于 Windows 10/11 64 位。包内已包含 Java 和 Electron，无需额外安装 Java 或 Node。
启动器使用 Windows 自带的 .NET Framework。导出结果保存在 renders，启动日志在 logs。

命令行导出：

```
投影预览.exe --cli "投影文件的完整路径.litematic" "输出图片的完整路径.png" 1024 1024 45 30
```

最后四个参数为宽、高、旋转角、俯仰角，均可省略。中文路径建议使用完整路径。

## 背景、全屏与首次启动

默认使用网格背景，网格仅用于预览，PNG / GIF 导出自动保留透明背景，不会把网格写入图片。预览区右上角可切换天空色、白色、深灰或自选背景色，也可导入不超过 10 MB 的 PNG / JPG 背景。图片按比例铺满并居中裁切，保存在 settings 中，重新启动后仍可使用。选择颜色或图片后默认导出对应背景；勾选“导出透明背景”可忽略背景。PNG 保留完整透明通道，GIF 支持全透明像素。

点击“全屏”或按 F11 切换全屏，按 Esc 退出。全屏期间仍可操作侧栏及预览。

左侧操作面板的右边缘中央有收起按钮；收起后点击左边缘的展开按钮即可恢复。收起状态会在重新启动后保留，预览自动扩大，已打开的投影、缩放和镜头角度不变。

启动时会显示作者 kinda sus 的欢迎弹窗。“网页链接”在默认浏览器打开指定网页；“关闭”只关闭本次弹窗，“后续不再显示”会保存选择，之后启动不再弹出。图标采用用户提供的 icon.jpg，内置到 EXE 和窗口中。

- 内缩面及未指定剔除方向的模型从自身所在位置读取光照，保留环境光下限。
- 预览透明背景使用与混合输出一致的预乘透明度，避免额外压暗。
- 删除旧诊断入口、测试投影、试验启动器代码及未使用的旧函数。

透明几何采用 BSP 空间分割：相交面先切分，再按相机所在位置确定前后顺序。玻璃、水和传送门共用同一棵树，CPU 导出与 3D 预览使用相同的分割几何。达到分片或树深度限制的极端情况会局部回退到深度排序。

## 1.0.17.1 透明背景、活塞、头颅与矿车修复

网格只作为透明区域的预览提示，导出 PNG / GIF 时自动透明。修复背景色参数覆盖透明选项的问题；CPU 和 GPU 预览均可使用相同的透明导出设置。

头颅改为明确的方块类型判断，避免将 piston_head 错送入头颅渲染，恢复普通与黏性活塞头的模型、贴图、朝向及长短状态。真实头颅不会作为完整方块参与遮挡；即使材质包提供完整方块代理模型，下方和相邻方块仍保留可见表面。

七类矿车根据所在铁轨计算朝向、位置与坡度，覆盖四个坡向、弯轨及平坡连接处，车内载物同步倾斜。位置与前后轮采样对照本地原版 OldMinecartBehavior 和 AbstractMinecartRenderer；脱轨时保留保存的角度。

验证包含实际 PNG / GIF 透明通道、48 组活塞状态、140 组地面/墙面头颅、七类矿车与十种轨道形状。

材质包列表新增“mc默认材质包”，附带的两款外观包可删除并记住删除状态。恢复导入后重新显示；补齐导入列表传入引擎、启动恢复列表和变更材质后重载当前投影，保证预览与导出实际使用列表中的材质。

## 1.0.17 CPU / GPU 实时预览切换

左侧“预览渲染”可选择 GPU 实时 3D 或 CPU 软件渲染，默认 GPU，选择保存在 settings/ui.json 并在重启后恢复。该选项只控制实时预览，PNG / GIF 继续使用 CPU 导出。

GPU 支持旋转、缩放、漫游和方块点选；CPU 支持旋转、缩放和光照选项，切换到 CPU 时会退出漫游并释放 GPU 网格。两种方式切换时保留轨道旋转、俯仰和缩放，CPU 模式直接使用引擎生成图片，不导出或上传 GPU 网格。CPU 不支持漫游及方块点选，界面会说明，并禁用漫游按钮。

CPU 拖动时使用低分辨率预览，停止后恢复清晰度。请求最多保留一个正在执行和一个最新待执行项，避免拖动事件堆积；切换方式或文件后忽略旧 CPU 图片。CPU 缩放在渲染相机中计算，“重新渲染”会实际重建场景。

## 1.0.16 大投影载入修复

大于 32 MiB 的模型改用有界分块传输，不再在主进程和预览窗口间一次复制整个文件。不透明几何按最多 32,768 面分批上传显卡，上传后释放对应的 CPU 顶点数组；透明几何继续保留共同的排序，不省略建筑或缩短可见距离。载入时显示进度，显卡分配失败会明确提示，不再自动尝试另一轮高内存的 CPU 预览。

使用《璃月港》（18,948,750 个方块、8,218,042 个渲染面）验证完整载入和漫游。原始网格为 1,187,539,588 字节，单次模型传输约 4.5 MiB，不透明层分为 190 批；小投影四个角度与原加载方式逐像素一致。更大模型仍受机器内存与显存容量限制。

logs/app.log 新增场景生成、网格大小、分块传输、预览就绪及进程退出记录；超过约 2 MiB 时保留一份旧日志，便于区分构建、载入和显卡阶段的错误。

## 1.0.15 查看方块后恢复视角

修正关闭方块详情、点击预览恢复漫游时镜头突然偏转的问题：恢复鼠标锁定后重置首笔非零位移，避免光标重新定位带动镜头。零位移的焦点事件不会提前消耗重置，同一次锁定的重复通知也不会丢弃后续转向输入；正常转向不增加等待，不重建场景。关闭按钮、点击预览恢复控制、锁定成功通知的不同先后顺序和连续转向已通过回归检查。

## 1.0.14 可选真实光照

左侧“光照”新增“渲染真正的光照”。默认关闭，保留 1.0.8 的明亮效果；开启后恢复 1.0.10 的照明：屋顶阻挡天空光，水、含水方块与树叶衰减天空光，火把、红石灯、熔炉和蜡烛等按保存的状态发光，局部面和内缩面使用插值光照与 AO。封闭且没有光源的室内会明显变暗。

切换后自动重建预览，保留当前旋转、缩放及漫游位置；选择会保存在 settings/ui.json，重启后继续使用。3D 预览、PNG 和 GIF 使用同一光照选项，视角变化继续复用已构建的模型。此模式恢复的是 1.0.10 的离线近似，不运行 Minecraft 的实时世界光照引擎。

对照原始 1.0.10 安装包验证光照、亮度组合、面取光和 AO；同时保留原始 1.0.8 默认模式回归。额外检查封闭房间、玻璃天窗、室内火把和跨远距离的稀疏区段。

## 1.0.13 交互与红石修复

“重新渲染”现在真正重建场景并重新上传预览，日志显示开始与完成，同时保留当前旋转、缩放及漫游位置。普通视角移动仍复用缓存。导入、移除或调整材质包后会更新 3D 模型。

漫游改为 Shift 下降、Ctrl 加速。鼠标锁定失败时不再悄悄切换为自由光标转向；预览区明确显示鼠标已释放，点击可重新锁定。Esc、窗口失焦及查看容器仍会主动释放鼠标，方便操作界面。

红石同一表面的底纹与覆盖纹理在构建时按材质顺序合成一次，避免重合面参与排序时出现叠色和转向闪烁。保留信号强度染色、0～15 数字标记和爬墙几何；带动画或不规则面的自定义模型保守保留原路径。已检查 16 档信号、点状/直线/十字/转角/爬墙五种形态与重建后的稳定网格，继续使用 1.0.8 光照。

## 1.0.12 大投影漫游优化

保留 1.0.8 光照，透明面只在需要保留原有明暗、纹理插值或弯曲表面时预细分，其他面直接交给 BSP 处理相交关系。参考投影的透明面从 117,849 降到 49,735（减少约 58%），全部导出面从 252,110 降到 183,996，网格从约 35.1 MiB 降到 25.7 MiB。四个角度的 CPU 预览与优化前逐像素一致。

漫游新增 16×16×16 区段的空隙连通性与视锥遍历，排除被完整实体墙隔开的不可见区段。玻璃、树叶、局部形状及门洞不会当作封闭墙；相机处在实体方块内、区域跨度极大或遍历成本过高时保守回退。轨道总览继续完整显示建筑，不通过缩短可见距离隐藏模型。全场景仍会在打开时一次构建，此版不包含后台分块加载。

修正图集透明留边造成的墙面细缝：留边现在复制贴图边缘颜色，动画帧更新时同步维护。漫游原地转向复用 BSP 分割面状态，区段分组减少临时数组分配。旧网格和不支持大索引的显卡继续使用兼容路径。

封闭房间、门洞、玻璃、负坐标和实际大投影共 104 个视角的遮挡开关对照逐像素一致；封闭房间一个视角的提交面数从 19,434 降到 7,890。开放式参考投影的区块遮挡收益有限，帧耗时受视角和显卡影响，不能把面数下降直接视为同幅度 FPS 提升。

## 1.0.11 恢复 1.0.8 光照

光照效果恢复为 1.0.8：使用旧版天空光、发光方块表和局部面取光规则，AO 也恢复旧版角点采样。保留预览静止缓存、交互低分辨率、光照颜色预计算、稀疏区段和内存容量检查。PNG / GIF 与 3D 预览共用恢复后的照明。

回归检查直接载入原始 1.0.8 安装包中的类，逐点比较密集与稀疏光照、亮度组合和方块面颜色，避免仅凭观感调亮。

## 1.0.10 预览缓存与交互性能

光照、AO 和染色在载入场景时合并为静态顶点颜色，后续视角变化直接复用模型、贴图和颜色，不重新计算场景光照。静止时保留已显示的画面，相同相机和窗口尺寸不会再次绘制。

拖动、滚轮缩放及漫游移动时，预览缓冲区最长边限制为 768 像素；停止操作约 160 毫秒后恢复窗口原生分辨率。投影矩阵及点选射线不受清晰度切换影响，PNG / GIF 导出分辨率仍由导出设置决定。可见区段不变时复用绘制范围，并按每帧一次提取视锥平面。

实际 252,110 面投影通过静止缓存、缩放、漫游恢复清晰度和点选检查。2694×1376 的测试窗口在交互时使用 768×392 的缓冲区，像素量降至约 8.1%；该环境中固定视角绘制耗时约从 0.60 毫秒降至 0.28 毫秒。该数字只衡量固定视角的绘制，转向时仍可能产生透明面重排，实际流畅度取决于投影和显卡。

## 1.0.9 性能与内存优化

- 清理切换投影后残留的实体合成贴图，保留并恢复基础材质；生成贴图像素不变时复用图集。
- 字体在同一资源会话内复用，相同文字、颜色和荧光效果的告示牌共用贴图；文字缓存设有容量上限。
- GIF 只构建一次场景，按实际使用的动画纹理选择循环；超出帧数上限时提示首尾衔接限制。原始帧使用临时文件保存，编码完成或失败后清理，减少高分辨率导出的内存占用。导出目标磁盘需留有临时帧空间。
- 光照按投影密度及容量自动选择密集或稀疏区段，区域跨度较大时不为中间空白分配整块数组。修正天空光穿过屋顶的问题，水与含水方块采用原版的 1 级光衰减，并补全火焰、熔炉、红石灯和蜡烛的发光状态。传播队列保留单份单元索引；邻居查询使用区域空间索引。
- 网格每面保存 4 个顶点，通过索引连接三角形；预览兼容旧网格格式和不支持大索引的显卡。
- 按 16 格区段进行视锥剔除，仅绘制可见区段；可见透明面仍统一排序。点选保持完整的方块和实体归属。
- 按方块和方向缓存面光照与 AO，局部面使用双线性权重，内缩面按深度插值；相邻台阶等模型按保守的面覆盖掩码剔除被完全遮住的面，透明和裁剪贴图不会作为实体遮挡。
- BSP 只在相机穿过分割面或可见面集合变化时重排，保留旧网格与旧显卡回退路径。

分块剔除已用实际大型投影的 8 个建筑内部视角验证，开关剔除的画面逐像素一致；交叉透明面的局部前后颜色、穿面触发和旧显卡回退也通过检查。密集与稀疏光照逐点对照 393,216 个单元一致，相距 2000 格的两个区域只需 16 个光照区段。模型推导的光照与遮挡仍是离线近似，不能完全替代原版运行时的体素形状。

## 从源码构建

需要 JDK 21 或更新版本、Windows 自带 C# 编译器，以及已安装的 Electron 依赖。默认会用完整 JDK 的 jlink 构建运行时；已有 runtime 时可使用 -ReuseRuntime。编译产物以 Java 21 为最低运行版本。
首次安装 Electron 可运行 install.bat。

```powershell
powershell -ExecutionPolicy Bypass -File verify.ps1
powershell -ExecutionPolicy Bypass -File package.ps1
```

package.ps1 会重新编译引擎、构建启动器和便携运行时，并生成：

- dist/投影预览/：便携运行目录。
- dist/投影预览-1.0.17.1.zip：可分发压缩包，EXE 直接位于 ZIP 根目录。
- 投影预览.exe：源码目录的启动器。

应用源代码在 src 和 webapp，启动器源码在 tools/launcher。
针对透明排序、含水树叶、告示牌、皮肤缓存、特殊模型和漫游查看的回归检查位于 tools/verify，不会进入分发包。便携运行时包含 HTTPS 所需的加密模块。

## 已知限制

复杂文字组件的加粗、斜体及翻译键未完整支持；指定清单以外的实体和旗帜图案等尚未支持。
静态模型、材质包和流体渲染来自内置资源；不同材质包可能影响透明分类与视觉表现。
