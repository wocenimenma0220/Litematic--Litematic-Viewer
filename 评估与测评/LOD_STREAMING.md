# 分块 LOD 与流式预览

此实现用于 GPU 实时预览。只有开启默认关闭的“大投影渲染”才使用此分块路径。
其中 LOD 独立控制远景简化，关闭 LOD 时按完整精度分块加载；关闭大投影渲染回到完整模型。
版本为 1.0.17.7。PNG / GIF 始终使用完整模型。

## 构建与资源生命周期

1. `SceneBuilder.sections()` 枚举包含方块或受支持实体的 16×16×16 所有权区块。
2. `prepareStreaming()` 一次准备材质、皮肤、光照与区域索引；使用临时区块注册头颅、告示牌，并按唯一红石状态提前生成拐角、爬墙合成贴图，然后固定图集布局。
3. `buildSection()` 只组装一个区块的几何。邻接剔除与平滑光照仍读取相邻方块，避免把区块边界当空气。
4. `StreamMeshExporter` 按视角优先写每个区块的四档几何，写完一个区块立即发布描述和已提交字节长度；全部写完后补齐标准 LMESH6 目录。队列有界，视角变化重排剩余区块。
5. Electron 主进程最多持有总览、增长中的完整细节两个只读文件能力；增长文件仅允许读取后端已提交的范围。单次传输最多 8 MiB，渲染进程不能任意指定文件路径。
6. `LodStream` 将每批最多 256 个完整区块描述合并进原有总览；新几何上传完成才替换旧粗档。完成后保留同一显示实例，不重读整份目录或清空显卡缓存。缓存重开仍按标准头部和完整目录读取。
7. 切换文件、预览方式或完整模型时，取消旧请求并释放 GPU 缓冲区和文件句柄；过期请求不会安装到新场景。

稳定图集和全局光照仍先准备，随后完整区块边生成边提供给预览器；总览可在全局光照阶段操作。
完整生成文件通过硬链接（不支持时复制）发布为不可变缓存，活跃读取路径保持稳定；不完整的增长文件不能作为缓存重开。取消会先关闭读取并停止生产者，再清理临时文件。
LOD 开关直接重排当前显示档位，预载选项控制已生成几何的提前加载范围。后台自动刷新合并，用户相机操作即时绘制。

## 光照

`SmoothLighting` 为面角采样天空光和方块光，结合遮挡、材质染色、方向亮度与 AO，生成每顶点 RGB。
内缩模型在内外采样平面之间插值；流体也使用顶点光照，背面保持对应角颜色。
发光方块的自身亮度由方块状态与模型发光值共同决定，对六个面都设置光照下限，并避免 AO 将灯体压暗。
透明 BSP 切分时插值颜色，非仿射四边形保留原来 0–2 对角线的两三角形插值。
CPU 图片与 GPU 精细预览使用相同颜色。

流式路径的稠密和稀疏光照直接查询压缩方块容器，不再额外展开全体方块引用。
稀疏传播只将可能增加邻居亮度的格子作为起始队列，已分配内存不会重复计入剩余内存检查。
光照仍是全局常驻数据，巨大投影仍需要足够的 Java 堆。

## LOD 与预算

| 档位 | 普通不透明 / 裁剪材质 | 透明材质 |
| --- | --- | --- |
| 0 | 原始几何 | 原始几何与区块 BSP |
| 1 | 2 格表面体素代理 | 与档位 0 共用精细页 |
| 2 | 4 格表面体素代理 | 合并为代表性表面，重新生成 BSP |
| 3 | 8 格表面体素代理 | 合并为代表性表面，重新生成 BSP |

实体、生成的头颅皮肤与文字保留原始几何；船舱水遮挡页在各档位共用。
水面代理保留代表性高度平面，避免把浅水全部变为大立方体。
粗档是外观近似，会改变部分小孔、薄片和玻璃的细节。水与熔岩表面、活板门、墙、栅栏和栅栏门保留原始几何，避免扩展后互相穿插。关闭 LOD 可检查其他完整外观。

镜头规划最多每 100 ms 一次，使用视锥和已有分块连通可见性。透视模式根据距离计算 16 格区块的像素大小，
正交总览根据投影比例计算；80 / 32 / 12 像素为档位阈值，边界有 20% 滞回，避免频繁切换。
判断档位始终使用完整显示尺寸，拖动时临时降低画面分辨率不会改变档位；镜头未变化时跳过重新规划。
小于约 8 MiB 的精细几何优先使用档位 0，仍受预算限制。

工作预算默认 256 MiB，界面可输入 32–16384 MB 并保存。包括保守估算的 GPU 几何、透明排序 CPU 数组、BSP、共享索引与约 17.3 MiB 传输临时空间。
实时调低预算时先取消并排空旧上传，再释放非活动缓存、细节和必要的活动区块；峰值统计从新预算生效时重新计量。
已加载的档位保存在活动/粗档/近期缓存中，缩放往返优先直接切换现有 GPU 缓冲，不重复读取和上传。
缓存空间不足才按较早使用顺序淘汰；缓存中的透明排序数组也计入同一预算。
三种界面模式为当前视距预渲染、完整投影预渲染和默认的边加载边渲染。预渲染以启动时的范围为准，
由近及远准备完整细节及四个缩放档位，活动镜头请求优先，逐页读取期间继续响应预览。可暂停/继续；超预算时停止后台工作并显示已缓存数量。
预渲染不会循环淘汰自己刚准备的内容，切换文件或 CPU 模式后释放相关缓存和文件能力。
若当前范围的全部最粗档占规划容量不超过 60%，先载入并保留这份整体，再优先升级近处细节；离开视野释放细节并恢复粗档。
漫游视距默认 6 区块，可调 1–128；以相机的 X/Z 区块坐标计算方形半径，垂直方向不限，负坐标使用向下取整。
范围限制同时作用于绘制、活动粗档与镜头精细页加载；改变视距会立即重新规划，不重建分块文件，取消范围外活动请求。
离开范围的几何进入近期缓存，在预算不足时释放；完整投影预渲染可主动准备范围外的细节。
轨道总览不使用漫游视距，完整 GPU 模型也按同一范围规则筛选绘制。CPU 导出始终保持完整几何。
较大的整体无法保留时使用可见区块工作集。规划容量为扣除传输与换档预留后的预算。
换档保留旧几何直到新几何完全上传，失败或取消也保留旧画面。每次安装或释放都会更新画面版本并请求重绘，
避免已载入区块被静止镜头的画面缓存忽略。统计使用计数器，加载队列顺序推进，避免逐块扫描整个场景。
若最粗档仍超出预算，优先保留近处区块，并在界面显示“内存预算已满”。
图集、原始投影、光照、目录、浏览器自身内存不在此几何预算内。

## LMESH5 二进制布局

头部、目录和 BSP 使用大端；几何顶点使用小端。偏移均相对于文件开头。

| 头部偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0 | 8 字节 | `LMESH5\0\0` |
| 8 | int32 | 结构版本 1 |
| 12 | int32 | 区块数 |
| 16 | uint64 | 目录偏移 |
| 24 | int32 | 目录字节数 |
| 28 | int32 | LOD 数 4 |
| 32 | uint64 | 档位 0 总面数，含水遮挡面 |
| 40 | float32 × 3 | 精细模型最小坐标 |
| 52 | float32 × 3 | 精细模型最大坐标 |

几何页最多 8192 个四边形，每面四个顶点。单顶点为 float32 XYZ（12 字节）、归一化 uint16 UV（4 字节）、
uint8 RGB 与填充（4 字节），共 20 字节；每面 80 字节。所有不透明页共用约 96 KiB 的 uint16 索引缓冲。
与原来每面 168 字节的顶点及索引相比，不透明几何本体减少约 52%。透明面另有排序数据。
UV 和颜色量化会产生很小的像素差异，档位 0 不代表逐位相同的旧顶点格式。

目录以 int32 区块数开始。每个区块包含：

- int32 × 3 区块坐标；float32 × 6 边界（覆盖所有 LOD）。
- 6 字节连通出口和 512 字节固体体素位图。
- 四组档位：int32 页数，随后每页 uint64 偏移、int32 字节数、int32 面数、int32 层。
- 层 0 为不透明、1 为裁剪、4 为混合透明、5 为水遮挡、6 为 BSP。
- BSP 页为 int32 节点数，每节点四个 float64 平面系数及四个 int32：首面、面数、前子节点、后子节点。

读入时检查文件范围、目录长度、总面数、重复区块、页大小、有限坐标和 BSP 结构。
目录最多 128 MiB，最多 200,000 区块。LMESH4 完整模型读取接口继续保留。

## 验证入口

- `tools/verify/LodRegression.java`：跨块、负坐标、重叠区域、图集动态内容、平滑光照、LOD 面数、原始模型点选与导出后缓存释放。
- `tools/verify/CompactLightRegression.java`：稠密、紧凑与稀疏光照逐格比较，覆盖不完整的边缘区块。
- `tools/verify/VisualFixRegression.java`：162 种红石连接状态的图集与分块几何，以及蛙鸣灯等 42 个发光面的亮度和六轴传播。
- `tools/verify/view-distance-settings.cjs`：默认值、非法值回退、1–128 设置持久化与完整 GPU 模型的视距。
- `tools/verify/lod-format.cjs`：索引读取、损坏文件拒绝、取消上传后无缓冲泄漏、实时预算调整、三种加载行为和缩放缓存复用。
- `tools/verify/SpecialAppearanceRegression.java`：旗帜新旧图案、颜色和朝向、讲台书籍、潮涌核心激活、光柱遮挡/染色/取景、48 种展示框摆放和旋转、幼年装备和成年纹饰，以及冻结图集后的分块完整性。
- `tools/verify/lod-ui.cjs`：实际应用六视角精细画面对照、自动重绘、12 次重复点击、连续拖动、8 次漫游点选、视距控件与即时范围更新、设置持久化、CPU / GPU 切换、预算压力、旧请求取消和 ZIP / 文件夹导入模式。
- `tools/verify/LodLargeBenchmark.java`、`RunLodLargeBenchmark.ps1` 和 `lod-large-ui.cjs`：真实大投影分块导出、Java 内存记录、GPU 总览完整覆盖及漫游测试。

已知边界：透明面采用区块内 BSP 与区块空间树排序；跨越区块边界的自定义透明模型可能仍有排序瑕疵。
PNG / GIF 临时构造完整 CPU 场景，导出峰值内存不受 GPU 工作预算约束；完成或失败后释放其预览缓存。
首次生成中断时只留下临时文件，成功后才替换目标模型；尚未实现后台多区块并行构建或磁盘 LOD 缓存淘汰。

真实样本为工作区《璃月港.litematic》，1178×298×950，约 1,895 万非空气方块。

| 精细几何 | 8,162,309 面，11,206 区块 |
| 最大单块临时几何 | 5,769 面 |
| 四档分块文件 | 899,415,004 字节，约 857.7 MiB |
| 分块导出耗时 | 66.0 秒；含资源与打开过程共 86.2 秒 |

| 总览加载 | 已生成文件起算，首块约 140 ms，全部总览约 13.1 秒 |
| 漫游 | 自动加载档位 0，移动后释放；全程工作预算峰值小于 256 MiB，无 WebGL 错误 |

32 MiB 压力测试中，20 个可见区块保持完整覆盖，同时使用 14 个精细块和 6 个不同粗档区块，并保留最粗整体用于切换。
六视角精细预览与旧浮点格式对照中，单通道差值大于 8 的像素占比：源码当前材质配置均小于 0.064%，
新安装的内置材质配置均小于 0.17%，符合紧凑 UV / 颜色量化预期。打包后的开关、导出、点选及预算测试也已通过。

## 1.0.17.3 稳定快照与有界输出

光照计算和生成图集完全完成后才启动区块生产者。构建器的可变缓存由一个生产线程独占；
主线程读取已发布网格并生成 LOD / 写页，等待队列最多两个区块。发布通过阻塞队列保证可见性，错误会停止生产与清理临时文件。
全局光照仍先稳定，没有在不同线程修改同一光照体积；完整索引和文件成功关闭后才原子替换目标。
这控制构建内存并重叠区块生成与输出，但当前界面仍在目录写完后打开文件，没有声称已实现渐进首屏。

## 1.0.17.5 独立总览、LMESH6 与持久缓存

此前 LMESH5 的目录在文件尾，完整文件未结束前不能交给读取端。本版保留这个稳定边界，先另写一份可独立打开的总览文件。
总览按 8 格单元聚合占用与资源颜色，坐标跨度过大时增大单元，使聚合数组不超过 1,000,000 格。
总览使用自己的白色图集，顶点携带颜色；不等待全局光照、皮肤和告示牌图集的完整几何构建。
玩家皮肤身份仍先解析用于缓存校验，存在联网请求时可能影响首屏；未把测试的离线时间作为联网承诺。

后台完整场景先稳定光照与生成图集，再生产区块；最远档复用同一聚合总览，在完整图集中注册独立白色图块。
近处完整档保留原始模型，中间档延续复杂边界保护；最远档的水、透明物与细小结构均为占用色块近似。
界面切换完整文件时保留视角，随后使用已有队列按视距读取与上传。完整精度的生成仍是全场景顺序流水线，尚未按当前视距优先构建。
任务编号同时用于状态、采用结果与取消；切换投影后拒绝旧编号，旧 GPU 上传另由代数检查防止覆盖新视图。

LMESH6 保留 64 字节头与四档目录。目录中的页描述扩展为 32 字节，顺序为：

| 字段 | 字节 | 含义 |
| --- | --- | --- |
| offset | 8 | 文件绝对偏移，大端 |
| bytes / quads / layer | 各 4 | 存储长度、面数、图层 |
| rawBytes / codec / crc32 | 各 4 | 解压长度、0=原始或 1=zlib Deflate、原始载荷 CRC32 |

顶点仍是每个 20 字节、每四边形 80 字节；普通顶点页上限 8192 面，即 640 KiB。
透明排序页独立编码，原始大小上限 16 MiB。JDK 使用 Deflate level 1，仅在比原始页小时使用压缩。
读取端只接受当前文件的有界读取权限，验证描述、范围、精确解压长度与 CRC32，禁止额外路径与超限解压。
解压任务单路执行，读取临时预算 80 MiB；这是有界缓冲估算，不能视作 Electron 进程 RSS 上限。
目录另有 128 MiB 格式上限。几何预算仍包括已有 GPU 数据、透明排序数据及原有临时预留；投影、光照、图集、索引另计。

缓存束在 `cache/scenes/<内容键>/` 保存 `mesh.lmesh`、`atlas.png`、`manifest.json`。
键包括原始投影字节、编译后的引擎内容、所有材质包内容与顺序、两个光照开关、实际解析皮肤像素与解析状态。
只在网格、图集与校验清单写完后原子移动发布；重新打开验证 SHA-256 与索引，再恢复流式点选所需的状态。
默认保留 4096 MiB，按包括清单在内的实际字节淘汰最久未使用条目，保护当前文件；关闭保留或单场景超限时只生成本次临时文件。
未增加 CPU 页缓存。统计提供 `bytesRead`、`decodedBytes`、`decodeMillis`、`transferPeakBytes`、`transferLimitBytes`、`cpuPageCacheBytes` 与目录大小。

LMESH5 读取仍兼容。PNG/GIF 使用完整原始模型重新生成所需 CPU 场景，不能据 GPU 磁盘命中推断 CPU 导出零构建。

## 1.0.17.7 增量目录与视角优先

冷打开先使用独立总览；准备稳定光照和图集后，增长文件的区块页立即发布。目录描述经状态接口每批最多 256 个传递，包含所有权坐标、包围盒、可见性和四档页描述。
读端同时保留总览文件，增长文件只开放已提交字节范围。总览按 16 格所有权对齐，每个区域的新细节上传完成后替换，最终完成只更新状态与统计。
LOD 开关不再重新进入 buildView，GPU 显示实例、已有缓冲与可复用档位保持。预载范围在完整模型生成后作用于已发布几何。
完整缓存只在标准头部、尾部目录与校验清单完成后发布，活跃文件路径不参与重命名。默认退出清理策略沿用 1.0.17.6。

已验证流中可读页、提交边界、增量合并、视角优先、取消、缓存重开和六视角图像。实际首批与总耗时分别记录在综合评估第 10 节；全局光照仍先准备，不能把总览时间当作材质就绪时间。
