# 投影预览 1.0.17.7

离线查看 Minecraft Litematica 投影（`.litematic`）的桌面软件：不需要启动 Minecraft，即可打开投影、
实时 3D 预览、漫游查看方块与容器内容，并导出 PNG 图片或动画 GIF。

渲染算法按 Minecraft 原版客户端复刻（面剔除、逐顶点 AO、CardinalLighting、multipart 方块状态、
流体高度场、colormap 染色、透明 BSP 排序），支持真实的天空光 / 方块光近似光照。

## 材料清单

左侧“投影材料”或文件菜单可查看、搜索建材与容器内容物，统计不生成渲染网格。
物品名称与数量分列，界面显示组数、余量及需盒数，不标注每组上限。内部按 Minecraft 26.3 物品注册及保存的自定义组件换算；
潜影盒按 27 格，达到半盒才显示向上取整的所需盒数。潜影盒不能嵌套，因此其自身不显示潜影盒装载数。

导出默认 XLSX，可选 CSV；两类合并到同一文件、分别导出两个文件、仅建材、仅容器内容物。
合并文件并排显示两组“物品／数量／需盒”，分别导出或单类导出只有对应组。
双台阶、门上下半、床头床尾与多数量方块按物品用量统计；保存的箱子各半仅统计一次，嵌套潜影盒和收纳袋内容展开。
未保存库存、未展开战利品表和未知堆叠上限会明确提示；不会把未知内容当作空容器。

每行提供原版贴图的一面或立方体图标，不受投影材质包替换影响。点击建材标题旁的“水桶换算为冰”，
把建材中的普通水桶按一桶水对应一块普通冰换算，与已有普通冰合并并重算组数、盒数；再次点击恢复。
导出跟随当前换算选择，容器实际保存的内容物不变，岩浆桶、细雪桶和生物桶不换算。
水源和含水方块按占用位置估算用水量，不推算无限水源的最少施工用量。

堆叠表覆盖 1658 个当前原版物品定义，并核对 1288 个原版方块的材料映射。
霜冰没有对应背包物品，保留霜冰计数并明确标注按普通冰的堆叠上限估算备料，不把它冒充成可获得的原版物品。

LiteTool 的首屏实测与 Voxy 的区块缓存源码分析已合并到 [投影渲染与区块缓存综合评估.md](评估与测评/投影渲染与区块缓存综合评估.md)。
1.0.17.5 按其第 6 节接入磁盘场景缓存、独立总览、压缩页和预算统计，并记录紧凑面与 16/32 格缓存单元的实验。
1.0.17.6 修复大型 NBT 读取超限与错误掩盖，默认退出清理渲染缓存。
1.0.17.7 按当前视角优先生成完整区块，边生成边载入；总览、已有材质区块与 LOD 缓存持续复用。

## 运行环境与启动

适用于 Windows 10/11 64 位。完整解压 ZIP 到一个文件夹，双击根目录的 **投影预览.exe**。
也可以把 `.litematic` 文件拖到 EXE 上，或用“打开方式”关联打开。请保留 EXE 旁的
`assets`、`bin`、`runtime`、`webapp` 文件夹。

包内已包含 Java 与 Electron，无需额外安装 Java 或 Node；启动器使用 Windows 自带的 .NET Framework。
导出结果默认保存在 `renders`，运行日志在 `logs`（启动器 `launcher.log`、应用 `app.log`）。

启动时会显示作者 kinda sus 的欢迎弹窗：“网页链接”在默认浏览器打开指定网页；“关闭”只关闭本次弹窗，
“后续不再显示”会保存选择，之后启动不再弹出。

## 界面与操作

界面为全中文，左侧操作面板 + 右侧 3D 预览区。

### 顶部“文件”菜单

打开投影（`.litematic`）…、导入材质包（ZIP）…、导入材质包文件夹…、导出 PNG…、导出动画 GIF…、退出。
未打开投影时导出项为禁用状态。

### 投影文件

“打开 .litematic…”按钮；打开后显示名称、作者、尺寸（x × y × z）、区域数与方块数。

### 玩家头颅

- “允许联网获取皮肤”复选框（默认开启，可在 `skins/settings.json` 中持久化）。
- 玩家名或 UUID 输入框 + “导入皮肤 PNG…”，用于导入本地皮肤覆盖。

### 材质包

列出“mc默认材质包”、内置包与导入包。两个内置外观包带“内置”标记，可点击 × 删除；导入包可上移 / 下移 / 移除，
**越靠下优先级越高**，列表保存在 `renders/packs.json`，重启后恢复。

### 预览渲染

下拉选择渲染方式，默认 **GPU · 实时 3D**，可切换为 **CPU · 软件渲染**：

- GPU 支持旋转、缩放、漫游与方块 / 实体点选。
- CPU 支持旋转、缩放与光照选项；不支持漫游与点选，界面会说明并禁用漫游按钮。
- 选择保存在 `settings/ui.json`，重启后恢复；两种方式切换时保留轨道旋转、俯仰和缩放。
- 该选项只控制实时预览，PNG / GIF 导出始终由 CPU 引擎完成。

GPU 默认载入完整模型。“大投影渲染”默认关闭，开启后先显示带状态提示的简化色块总览，再后台准备光照与完整模型；其设置重启后保留。
完整文件准备好后切换预览并保留当前视角，近处页面按需载入。总览阶段可旋转、缩放与漫游，完整模型就绪后开放点选、材料与导出。
大投影模式下可独立开启“按距离调整细节（LOD）”。最远档沿用轻量色块作为保底，离开视野释放精细几何。
拖动期间继续显示已有区块，新档位就绪后再替换；单纯点击不会重新载入模型。
界面显示已载入区块与几何预算。关闭“大投影渲染”回到完整模型；仅关闭 LOD 则仍分块加载完整精度，缓存不足时暂停新增加载。
近处完整档和中间档保留水面、活板门、墙与栅栏的重要边界；最远色块档只表达大致占用与颜色，
近距离点选始终按原始模型计算。PNG / GIF 使用原始完整模型，不受预览 LOD 影响。

首次打开先独立发布总览，再准备全局光照和稳定图集；完整区块按当前视角与视距优先生成，生成后立即可载入，其余后台继续。
新细节上传成功后才替换对应总览；完整模型准备完成时复用原有显示实例，不重读整份索引或清空显卡区块。切换 LOD 只调整已有区块档位。
界面区分整理区块、计算全局光照、准备特殊贴图、已生成区块与当前视角载入进度。全局光照仍是首批材质区块之前的等待阶段，总耗时仍需优化。
原始投影、光照、图集与索引不计入几何预算，
因此 256 MiB 不是软件的总内存上限。架构、格式及验证方法见 [LOD_STREAMING.md](评估与测评/LOD_STREAMING.md)。

大投影场景缓存保存在 `cache/scenes`，默认限额 **4096 MB**；可设置 **256–131072 MB**，填 **0** 关闭持久保留。
默认勾选“关闭应用时清理渲染缓存”：退出时先停止后台任务、关闭模型文件并等待引擎退出，再清理 `cache/scenes`、`cache/previews` 与普通模式的 `renders/.gpu` 临时模型。
取消勾选后，完全相同的投影内容、材质包内容与优先级、光照和已解析皮肤可在重启后复用。修改时间或文件大小相同也会检查内容。
清理只针对生成的渲染数据，配置、资源包、导出文件与本地皮肤继续保留。
损坏缓存会重新构建，写完全部文件后才发布缓存清单；“清理未使用缓存”保留正在使用的场景。
LMESH6 每页独立压缩和校验；界面分别显示磁盘用量、几何工作集与读取临时空间，读取临时上限 80 MB，未额外保留 CPU 页缓存。
未完成构建与总览属于本次临时文件，另行统计；再次打开会清理上一份总览，超过 24 小时的遗留临时项会在后续启动准备时清理。
PNG / GIF 继续从原始完整模型生成，不使用色块总览；GPU 场景命中不代表 CPU 导出跳过模型生成。

大型 `.litematic` 的方块数组按页压缩保存，空页和相同数值页单独简化；访问时共享每线程最多 2 MiB 的解码页。
专用读取路径允许最多 16 GiB 的逻辑解压数据，同时限制常驻数据预算为堆上限的三分之一且不超过 1 GiB；普通 NBT 读取仍保留原有较低限额。
GZIP 由文件头识别，损坏、截断和超限会报告真实读取错误及文件名，避免被 `Unknown(31)` 掩盖。
已验证《故宫》122 区域读取、总览和切换投影；尚未验证它全部完整材质构建完成。该文件含约 4.77 亿非空气方块，完整细节仍属于重负载。

“预览几何缓存上限”默认 **256 MB**，可输入 **32–16384 MB** 的整数并保存，修改后直接调整当前缓存，无需重新生成模型。
调低时会先取消过期上传、释放缓存和多余细节，再继续预览；投影、光照、图集及 Java / 浏览器自身内存另外计算。

“模型准备方式”有三种：

- **当前视距预渲染**：后台准备漫游位置周围的完整细节与缩放档位；轨道总览以投影中心为准。
- **完整投影预渲染**：后台准备整幅投影的完整细节与缩放档位，前台可继续旋转、缩放和漫游。
- **边加载边渲染**：默认方式，按镜头需要补充区块，同时显示已有结果。

预渲染可以暂停或继续，界面单独显示进度。三种方式都复用缓存：放大、缩小后保留已载入档位，
只有缓存空间不足时才淘汰较早使用的内容。完整预渲染超过上限时会暂停并提示，可提高上限后继续。
这里准备的是实时预览使用的几何缓存；首次打开时，已生成的区块会直接加入预览，其余继续构建。

“漫游视距”默认 **6 区块**，可拖动滑杆或输入 **1–128** 的整数，重启后保留选择。
以相机所在的区块为中心，限制周围 X/Z 水平方向的区块范围，每区块宽 16 格，垂直方向不限。
LOD 预览只按需读取此范围内的区块，扩大视距会补充加载，缩小或移远会释放范围外几何；关闭 LOD 时也按此范围显示。
轨道总览和 PNG / GIF 导出保持完整投影。该设置用于 GPU 漫游，CPU 预览下禁用。

### 光照

“开启光照渲染”位于平滑光照旁边，默认开启。关闭后跳过光照计算，直接显示材质与染色；
方块、流体、头颅及实体不再使用明暗与 AO。预览、PNG、GIF 共用此设置，切换保留视角并保存。
遮光玻璃的阻光规则独立于贴图透明度，已修复屋顶与隔墙漏光。

“平滑光照”复选框，新设置默认开启，已保存的开关选择继续保留。开启后计算天空遮挡与方块光源，
屋顶阻挡天空光、水与含水方块和树叶衰减天空光、火把 / 红石灯 / 熔炉 / 蜡烛按保存状态发光，
封闭无光源的室内会明显变暗。方块和流体表面按顶点采样并插值，保留 AO 与材质染色。
蛙鸣灯等发光方块的六个面保留自身发光亮度，避免被邻居阴影压暗；光照向六个方向传播。
关闭后使用原有明亮效果。切换后自动重建预览并保留当前视角，选择重启后继续生效。

### 视角

进入漫游默认位于投影几何包围盒中央，不再按投影尺寸退到远处。
“显示自身坐标”可在漫游中显示当前 X/Y/Z，移动时实时更新；坐标使用投影本身坐标，保留小数与负值，选择重启后保存。

| 控件 | 范围 | 默认 |
| --- | --- | --- |
| 水平旋转 | 0–360°，步进 1 | 45° |
| 俯仰角 | −90–90°，步进 1 | 30° |
| 缩放 | 0.05–20×，步进 0.05 | 1.00× |

六个预设视角：等轴 45/35.264、斜二测 45/30、正视 0/0、俯视 0/89、背视 180/0、左视 −90/0。

在预览区按住左键或右键拖动即可旋转（水平环绕、俯仰限制在 ±85°），滚轮缩放；
拖动时先出低分辨率预览，停止约 160 ms 后自动恢复清晰度。

### 输出

分辨率 512 / 1024（默认）/ 2048 / 4096；“导出透明背景”默认勾选；背景色默认 `#ffffff`。

### 背景、全屏与面板

默认使用网格背景，网格只用于预览，PNG / GIF 导出自动保留透明背景，不会把网格写入图片。
预览区右上角可切换：网格背景、游戏天空色、白色、深灰、自选背景色、自定义图片。
可导入不超过 10 MB 的 PNG / JPG 背景，按比例铺满并居中裁切，保存在 `settings` 中，重启后仍可使用。
选择颜色或图片后默认导出对应背景；勾选“导出透明背景”可忽略背景。

点击“全屏”或按 **F11** 切换全屏，按 **Esc** 退出；全屏期间仍可操作侧栏与预览。
左侧面板右边缘中央有收起按钮，收起后点击左边缘展开，收起状态重启后保留，预览自动扩大，
已打开的投影、缩放和镜头角度不变。

## 漫游查看

按 **V** 进入漫游模式（GPU 预览下可用），鼠标锁定后移动即可转视角。

| 按键 | 作用 |
| --- | --- |
| W / A / S / D | 前后左右移动 |
| 空格 | 上升 |
| Shift（左右均可）或 C | 下降 |
| Ctrl（左右均可） | 加速 |
| 鼠标移动 | 转向（70° 透视视场） |
| 左键 | 查看准星所指方块或实体 |
| Esc | 释放鼠标（或关闭详情面板） |
| V | 退出漫游 |

漫游使用内置的原版 Minecraft 十字准星。进入漫游时会锁定鼠标以持续转向；若系统拒绝，
视角暂停并提示“鼠标锁定失败，请点击预览区重新锁定”，点击预览区可重试。
锁定成功后第一段非零位移会被丢弃，避免光标重新定位带动镜头偏转。按 Esc 或切换窗口会释放鼠标。

漫游支持 16×16×16 区段的空隙连通性遍历，被完整实体墙隔开的不可见区段不会提交绘制；
玻璃、树叶、局部形状及门洞不会当作封闭墙，相机处在实体方块内或遍历成本过高时保守回退。

## 方块与实体查看

漫游中把准星对准目标后按左键，弹出详情面板：

- **方块状态**：名称（本地化的中文名，缺失时回落到英文与 ID）、投影坐标与所属区域、
  状态属性表（朝向、含水、点亮、红石强度等，属性名与取值均中文化），以及投影文件里保存的原始属性。
- **实体状态**：实体种类、ID、名称、坐标、距离，以及 yaw / pitch、骑乘、木材、幼年、南瓜头、生命值等。
- **容器内容**：按容量表识别箱子 / 陷阱箱 / 末影箱 / 潜影盒（27）、发射器 / 投掷器 / 合成器（9）、
  漏斗 / 酿造台（5）、熔炉族（3）、装饰陶罐 / 讲台 / 唱片机（1）、雕纹书架（6）；
  双箱自动配对并合并两侧槽位。

容器合并规则：**相同物品且 NBT 相同**的多组内容合并显示数量并记录来源槽位。比较时只忽略物品根层的
数量（Count）与槽位（Slot），保留附魔、自定义名称、耐久、嵌套内容以及 NBT 数字类型的差别；
字段排列顺序不同不影响合并。点击物品可展开完整数据。该功能只读，不会修改投影。

投影未保存容器数据、战利品尚未生成、缺少另一半箱子或末影箱（内容属于玩家数据）时，
面板会显示对应提示，避免误报为空容器。

打开详情面板会自动释放鼠标；关闭面板或点击预览区可继续漫游，Esc 关闭面板并保持视角暂停。
准星与面板只用于预览，不会进入 PNG / GIF 导出。

## 玩家头颅与皮肤

玩家头颅支持真实皮肤，包含基础头部和帽子外层，保留地面 16 个旋转方向及墙面四个朝向。
头颅使用局部形状，不会按完整方块剔除下方或相邻方块的面；活塞头单独使用活塞模型，不进入头颅渲染。

- 兼容新版 profile 与旧版 `SkullOwner`；优先使用投影保存的皮肤纹理地址，只有玩家名或 UUID 时
  通过 Minecraft 官方公开接口查询（`api.mojang.com` / `sessionserver.mojang.com`），无需登录账号。
- 首次缺少皮肤时联网获取，之后优先使用 `skins/textures` 与 `skins/profiles` 本地缓存。
  下载为 4 线程并行，连接与读取超时各 4 秒，单文件上限 2 MB，整场景最多等待 20 秒。
- 侧栏“玩家头颅”可关闭联网，关闭后仍能使用缓存；没有资料、下载失败或超时时继续显示 Steve。
- 只接受 `textures.minecraft.net` 下的纹理地址，投影内嵌的任意 URL 不会触发下载。
- 可输入玩家名或 UUID 导入 64×64 或旧版 64×32 皮肤 PNG，保存为 `skins/local` 中的本地覆盖，
  优先于在线皮肤，并对旧皮肤应用原版透明修复。
- 缓存保留首次获取的皮肤，玩家换肤后可删除对应缓存重新获取；骷髅、僵尸等其他头颅目前仍使用 Steve 占位模型。

## 告示牌文字

告示牌默认使用内置 Minecraft 字体：英文来自原版 bitmap provider，中文来自官方资源索引中的 Unifont，
字体文件位于 `assets/builtin/minecraft-font`，随便携 ZIP 一起解压，无需安装系统字体或联网下载。
支持中英文、数字和常见标点，其他文字脚本不显示（会被明确报告，而不是画成乱码）。

- 普通文字使用原版染色后的暗色并跟随环境光照；使用荧光墨囊的文字保持全亮，带原版描边。
- 正反面分别读取颜色与荧光标记，保留四行中的空行。
- 支持普通、悬挂与墙置告示牌，按牌型宽度裁切过长文字。
- 文字面板按（文本、颜色、荧光、牌型）缓存，相同内容在不同位置共用同一张贴图。
- 3D 预览、PNG 和 GIF 使用同一组文字像素。

## 特殊模型

参考 Enhanced Block Entities 1.21.4，补全原版需要方块实体渲染器才能正确显示的静态模型：

- 普通箱子、陷阱箱、末影箱及双箱。
- 潜影盒全部 17 种颜色和六个朝向。
- 钟的四种悬挂方式。
- 装饰陶罐随朝向旋转的四面纹样（纹样从投影保存的数据读取，兼容新旧格式；没有纹样的面使用砖面）。
- 床继续使用当前原版资源的方块模型。

EBE 模型的来源说明和 LGPL 许可证随包放在 `assets/builtin/static-block-entities`。
另有内置包 `fast-chest`（快速箱子模型）、`block-entity-textures`（头颅模型与图集条目）与
`minecraft-font`（字体），这些属于运行所需的基础设施，界面上不列出。

## 指定实体

读取投影中保存的普通实体并静态渲染（不运行生物 AI、物理或行走动画）：

- **矿车**：普通、运输、动力、漏斗、TNT、命令方块、刷怪笼矿车。
- **船**：各木材的船与运输船共 11 种，包括竹筏与运输竹筏；兼容旧版通用 `boat` / `chest_boat`
  的 `Type` 木材字段和新版各木材实体 ID。
- **雪傀儡**（含南瓜头开关）、**铁傀儡**（按生命值显示裂纹）、**猪灵**（成年与幼年）。
- **物品展示框、荧光物品展示框**：六个朝向、八档物品旋转、隐形框内物品及内容查看。

模型保留保存的位置、水平朝向和头部俯仰；矿车支持载物与自定义 DisplayState；猪灵支持常见盔甲与
手持物品；乘客使用载具座位位置并避免重复显示；完全浸没的船保留水面，船舱深度遮挡会阻止水面
显示在船内部，竹筏保持开放结构；负尺寸区域的方块和实体使用各自正确的坐标起点。

轨道上的矿车从轨道形状计算位置、朝向与倾斜，覆盖四个坡向、弯轨和平轨与斜轨连接处，车内载物同步倾斜。
支持普通、动力、探测与激活铁轨；没有轨道时保留投影保存的姿态。此处理用于静态展示，不模拟矿车运动。

漫游准星也可点选这些实体，查看实体状态和保存的数据；运输矿车、漏斗矿车和运输船的内容物按
相同物品及相同 NBT 合并。预览统计会显示实际渲染的实体数量，以及隐形与不支持的数量。

## 材质包与内置资源

材质包列表将原版贴图显示为“mc默认材质包”，作为基础材质。两款附带的外观材质包可点击 × 删除，
删除后立即重新应用到当前预览，重启后也不会自动加载；从 `assets/builtin` 重新导入对应 ZIP 可恢复。
删除只移除加载记录，保留附带 ZIP 文件。模型、字体和头颅等渲染支持资源继续由程序管理。

资源栈顺序为：`assets/vanilla`（原版，恒为最低） → `assets/builtin`（内置包，按文件名排序）
 → 用户导入包（最高优先级）。同名资源后者覆盖前者，缺失的部分自动回落到原版。

- 支持导入 zip 或文件夹，标准 `assets/<命名空间>/...` 布局。
- 内置原版资源包含 1288 个 blockstates、4192 个模型与约 1400 张方块贴图。
- 随包附带的两个外观包：`XK redstone display 26.3.0.zip` 与 `护眼大补丸1.19-26.3.zip`。
- 图集合并 `atlases/*.json` 的全部 sources，支持目录与单贴图来源，动画贴图按 `.mcmeta`
  （frametime / interpolate / frames）逐帧播放。
- 导入、移除或调整材质包后会更新 3D 模型；读不出的包只警告，不影响启动。

染色按模型的 tintindex 复刻原版：草、树叶（按树种）、水、红石线（按 power 0–15 渐变）、
作物茎（按 age）、睡莲等；生物群系色图在离线环境固定使用平原近似。

## 渲染实现

**光照。** 默认使用明亮的固定光照；开启“渲染真正的光照”后走真实的天空光 / 方块光传播，
包含逐顶点 AO（按原版权重与退化规则）、局部面与内缩面的插值与深度混合、按方块和方向缓存的面光照，
以及原版 lightmap 亮度曲线。密集与稀疏两种光照体积按投影密度和可用内存自动选择，
相距很远的区域只为占用区段分配数组。

**透明排序。** 玻璃、水、传送门共用一棵 BSP：相交面先切分，再按相机所在位置确定前后顺序，
CPU 导出与 3D 预览使用相同的分割几何。没有 BSP 时回退为按视深排序（超过 2048 面使用
64 位深度基数排序）；视角不变时复用上一次的顺序。达到分片或树深度限制的极端情况会局部回退。

**剔除与性能。** 面剔除依据从模型反推的方块形状（要求每面恰好一个铺满整面的四边形且贴图完全不透明），
玻璃、树叶、漏斗等不会被误判为遮挡体；另有 16×16 覆盖掩码用于部分遮挡。可见几何按 16 格区段
做视锥剔除与连通性遮挡剔除，并且只对可见区段提交绘制。

**大投影。** 大于 32 MiB 的网格改用有界分块传输（每块 8 MiB），不透明几何按最多 32,768 面
分批上传显卡并在上传后释放对应的 CPU 顶点数组，载入时显示进度。已用 18,948,750 个方块、
8,218,042 个渲染面的投影验证完整载入与漫游；更大模型仍受机器内存与显存容量限制。

**导出与预览共用同一场景。** PNG、GIF 和 3D 预览使用同一份几何与光照；GIF 只构建一次场景，
逐帧只更新动画贴图、光栅化和编码。

## 导出

| 格式 | 参数 | 说明 |
| --- | --- | --- |
| PNG | 512 / 1024 / 2048 / 4096 | 保留完整透明通道；建议文件名 `<投影名>_<分辨率>.png` |
| GIF | 64 帧上限，每帧 5 厘秒 | 无限循环、逐帧透明；实际帧数取场景实际使用动画的最短公共周期 |

导出过程显示进度遮罩（读取投影 / 准备 3D 视图 / 载入大投影 N% / 渲染 N×N / 渲染动画…），
完成后显示尺寸与耗时，并提供“在文件夹中显示”。导出路径由另存为对话框决定，默认文件名取自投影名。

若存在无法解析的模型或贴图，导出时会提示数量与前几项，而不是静默画出粉黑格子。

## 命令行

打包后的启动器支持命令行导出，不需要打开界面：

```text
投影预览.exe --cli "投影文件的完整路径.litematic" "输出图片的完整路径.png" 1024 1024 45 30
```

最后四个参数为宽、高、旋转角、俯仰角，均可省略（默认 1024 1024 45 30）。中文路径建议使用完整路径。

也可以直接调用 Java 引擎（源码运行时）：

```text
java -Dlitematicrender.home=<项目根> -cp bin io.github.litematicrender.Main --render <x.litematic> [out.png] [宽] [高] [旋转] [俯仰]
java -Dlitematicrender.home=<项目根> -cp bin io.github.litematicrender.Main --anim   <x.litematic> [out.gif] [尺寸] [帧数]
java -Dlitematicrender.home=<项目根> -cp bin io.github.litematicrender.Main --serve
```

`--anim` 默认输出 `animation.gif`、尺寸 512、最多 64 帧、每帧 5 厘秒。

`--serve` 启动引擎的 JSON-RPC 服务（stdin/stdout，一行一个 JSON），供 Electron 外壳驱动，
方法包括：`ping`、`loadResources`、`open`、`render`、`renderPreview`、`renderAnimation`、
`exportScene`、`pickBlock`、`skinSettings`、`setSkinOnline`、`importSkin`、`cancel`、`shutdown`。

## 项目结构

```text
litematic-render/
├─ src/                  Java 渲染引擎源码（io.github.litematicrender）
│  ├─ nbt/               NBT 读写
│  ├─ schematic/         .litematic 解析
│  ├─ world/             方块注册表、状态、形状
│  ├─ resource/          资源包（vanilla / zip / 文件夹）多包叠加
│  ├─ model/             方块模型与 multipart 烘焙
│  ├─ render/            图集、染色、光栅化、GIF、网格导出
│  │  ├─ scene/          场景构建、光照、BSP、实体、方块实体几何
│  │  ├─ raster/         正交相机与软件光栅器
│  │  └─ skin/           皮肤解析与缓存
│  └─ serve/             JSON-RPC 服务、渲染引擎、方块检查
├─ webapp/               Electron 外壳（界面、GPU 预览、IPC）
│  └─ renderer/          index.html / style.css / renderer.js / gpu-view.js
├─ assets/vanilla/       内置原版资源
├─ assets/builtin/       内置资源包
├─ tools/launcher/       启动器源码（C#）与构建脚本
├─ tools/verify/         回归与验证脚本
├─ bin/                  编译产物
├─ runtime/              jlink 精简 Java 运行时
├─ package.ps1           打包脚本
├─ verify.ps1            构建后验证脚本
└─ install.bat           首次安装 Electron 依赖
```

Java 引擎约 9,500 行（59 个文件），Electron 外壳约 3,000 行。引擎是纯 CPU 计算、不依赖 GUI 库，
界面与交互由 Electron 完成，两者通过行式 JSON-RPC 通信。

## 从源码构建

需要 JDK 21 或更新版本、Windows 自带的 C# 编译器，以及已安装的 Electron 依赖。
首次安装 Electron 可运行 `install.bat`（仅源码运行需要，绿色 ZIP 已内置）。

```powershell
powershell -ExecutionPolicy Bypass -File verify.ps1
powershell -ExecutionPolicy Bypass -File package.ps1
```

- `verify.ps1`：编译引擎，用工作区中最大的 `.litematic` 从四个旋转角渲染，检查进程退出码、
  四张图是否互不相同（防止旋转被忽略），并断言日志中没有未解析的模型 / 贴图。
- `package.ps1`：重新编译引擎、构建启动器与便携运行时，产出 `dist/投影预览/` 便携目录与
  `dist/投影预览-<版本>.zip`（EXE 直接位于 ZIP 根目录，无外层文件夹），并打印 EXE 与 ZIP 的 SHA256。
  常用开关：`-ReuseRuntime`、`-SkipElectron`、`-SkipRootLauncherCopy`、`-JdkHome`、
  `-Version`、`-PackageName`。

工具脚本：

- `tools/launcher/build-launcher.ps1`：仅重新编译启动器（用 Windows 自带 `csc.exe`，无需 SDK）。
- `tools/verify/`：透明排序、含水树叶、告示牌、皮肤缓存、特殊模型、实体、红石、光照、
  区段遮挡、大投影网格分块、界面与设置持久化等回归检查，不会进入分发包。
- `tools/verify/RunHiddenElectron.ps1`：无窗口运行 Electron 测试脚本，带 180 秒超时。

版本号需要手工同步四处：`package.ps1` 的 `-Version` 默认值（决定 ZIP 名）、
`webapp/package.json` 与 `package-lock.json`、`tools/launcher/Launcher.cs` 的程序集版本、本文件标题。

## 已知限制

- 复杂文字组件的加粗、斜体及翻译键未完整支持；标记以外的文字脚本（含部分中文外字符）不显示。
- 内置字体之外的字形需要额外资源；纯中文以外的生僻字同样受限于 Unifont 覆盖范围。
- 实体渲染范围以本文“指定实体”清单及物品展示框为准，其他实体不显示。猪灵已支持幼年专用盔甲和成年盔甲纹饰；
  常见物品支持厚度和方块模型，复杂物品组件、自定义运行时物品模型及附魔闪光仍未完整支持。原版此版本不为幼年盔甲绘制纹饰。
- 旗帜支持 16 色底色、新旧 NBT 图案及地面/墙面朝向；讲台有书时显示打开的书籍模型。
- 展示框及荧光展示框支持六个朝向、八档物品旋转和隐形框内物品。投影通常不携带世界地图像素，因此地图使用物品外观。
- 潮涌核心根据保存的水与框架判断未激活/激活外观，旗帜、书籍、核心和信标光柱均为静态快照，不包含运行时动画及核心眼睛朝向镜头的效果。
- 信标检查完整第一层底座、顶部遮挡及染色玻璃，并显示有颜色过渡的光柱；不模拟效果、动画或远处光柱随视距变粗。
- 床的枕头直接来自原版床头贴图，材质包替换同步生效；原版没有独立的枕头颜色状态。
- 模型推导的光照与遮挡是离线近似，不能完全替代原版运行时的体素形状；
  静态模型、材质包和流体渲染来自内置资源，不同材质包可能影响透明分类与视觉表现。
- GPU 大投影可先看独立总览，完整区块按视角优先逐块补充；稳定图集与全局光照仍先准备，首批材质前的等待与完整准备总耗时仍需优化。
